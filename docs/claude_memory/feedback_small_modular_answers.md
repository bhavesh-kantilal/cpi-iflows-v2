Break big questions into small, modular parts: answer one topic, wait for the user, then the next. Do not put the whole analysis into one reply.

**Why:** The user (2026-11-27) said a long reply that covered repo split, knowledge files, assumptions and code review at once was too much to process: "let's break this down into smaller, modular problems and answers."

**How to apply:** When a message has several questions, plan them as separate steps, answer the first one briefly, and end each step with a short report before moving on. Applies in every repo, including cpi-mappings-v2 and cpi-iflows-v2 (see [[project-repo-split-v2]]).
